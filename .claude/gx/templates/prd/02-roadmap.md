# Roadmap

Dates stay TBD until the feature analysis has sized every feature (S, M, L). A phase closes at its gate, not on a date.

## Phases and gates
| Phase | Name | Gate | Gate criteria | Target date |
|-------|------|------|---------------|-------------|
| P0 | Discovery | Gate 0 | PRD v1.0 signed; analysis reviewed (keep/cut/change/defer); roadmap approved | TBD |
| P1 | Foundation | Gate 1 | Login, roles, tenant isolation, CI, staging deploy and one thin slice work end to end with tests green | TBD |
| P2 | Core build | Gate 2 | Every Must feature passes its acceptance criteria on staging, demoed and signed off | TBD |
| P3 | Harden | Gate 3 | Should features done or deferred; load, security, accessibility, compliance checks passed; migration rehearsed; rollback written; users trained | TBD |
| P4 | Launch | Gate 4 | Two weeks live with no severity-1 issue; support runbook handed over; success metrics measured | TBD |
| P5 | Operate | - | Continuous improvement under change control | - |

## Milestones
A milestone is an outcome the client can verify, 2-4 per phase, one demoable every 1-2 weeks.
