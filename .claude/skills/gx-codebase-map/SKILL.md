# Codebase map

Reading the repo to answer "where is X" burns tokens and attention. The map answers it in one read.
It is generated by `.claude/gx/bin/codemap.py` and refreshed automatically: the PostToolUse hook
updates it after every Edit/Write, and SessionStart rebuilds it if stale.

## Navigation order (cheapest first)
1. `.claude/map/MAP.md` — modules with size, dependencies, dependents and the tables/functions they touch.
2. `python3 .claude/gx/bin/codemap.py find <term>` — files, symbols, routes, tables, env vars matching a term.
3. `.claude/map/modules/<module>.md` — every file in that module, one line each.
4. `.claude/map/ROUTES.md` (pages, API endpoints, server/edge functions) and `DATA.md` (tables, who reads, who writes).
5. Only then open source files, reading the line range you need.

## Before changing a file
`python3 .claude/gx/bin/codemap.py impact <file>` lists transitive dependents, affected routes/pages
and files touching the tables it defines. Paste the summary into the plan's impact section. Exit code 1
means something depends on it.

## Setup in a repo
```bash
python3 .claude/gx/bin/codemap.py build      # first time; ~1s per 1,000 files
python3 .claude/gx/bin/codemap.py check      # FRESH or STALE + what changed
```
Tune `.claude/gx/config.json`: `module_depth` (default 2), `modules` (glob → module name, e.g.
`"supabase/functions/*/**": "edge-functions"`), `exclude` (globs). Commit `.claude/map/` so reviewers
see structure diffs in PRs; it is deterministic text.

## Limits (state them when it matters)
Extraction is regex-based. NOT traced: dynamic imports, string-built queries, DB triggers and SQL
functions, reflection/DI containers, calls across separate repos, runtime config. "Read by/written by"
for tables is heuristic. Treat the map as the index, the code as the truth: verify a detail by reading
before relying on it for a risky change. If the map is wrong about something important, fix the
config or extend `codemap.py`, don't work around it.

## Supported conventions
TS/JS (imports incl. tsconfig `paths`, Next.js app/pages routes, route handlers, server actions,
Express-style routers, fetch/axios calls, Supabase `.from/.rpc/functions.invoke`), Python (Django
models and urls, imports), Dart (package/relative imports, classes), Go (symbols), SQL (tables, FKs,
functions, policies), Prisma models, env var reads across languages.
